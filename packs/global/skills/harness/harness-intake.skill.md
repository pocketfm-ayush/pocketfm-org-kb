# Skill: Harness intake

**When:** Start of a task, or when the ask is ambiguous.
**Borrowed from:** Codex planner Phase 1 clarify; clarity-gate patterns.

## Do before research/plan/code

Ask (or explicitly defer with ASSUMPTION) covering:

1. Goals & success criteria  
2. Scope & non-goals  
3. Repo / pack / env (QA vs prod)  
4. Data & integrations at risk  
5. Auth / permissions  
6. Test & validation commands  
7. Deploy / rollback expectations  
8. Deadline / human gates  

Prefer **5–10 focused questions** when ambiguity is high. Do not invent product
defaults. Log deferred items as `ASSUMPTION: …`.

## Exit

`INTAKE: READY` with listed assumptions, or `INTAKE: BLOCKED` with questions.
